# 수질 데이터 표준 용어 사전

공공 수질 데이터의 컬럼명이 소스마다 제각각이라는 문제를 풀기 위한 사전이다.
초안 `수질_측정항목_표준사전_초안.xlsx`를 법령 원문·실데이터와 대조해 다시 만들었다.

- **최종 저장소는 PostgreSQL이다.** CSV/엑셀은 부트스트랩과 사람 검수용 표현일 뿐이다.
- **동의어는 계속 쌓인다.** 새 데이터셋을 읽다 매칭에 실패한 컬럼은 큐에 쌓이고, 사람이 승인하면 사전에 편입된다.

```
schema.sql              PostgreSQL 스키마 (테이블 5 + 뷰 3 + 함수 4)
seed.sql                시드 데이터 INSERT문
build_dictionary.py     시드 생성기 (CSV + seed.sql)
make_xlsx.py            CSV -> 검수용 엑셀
check_dictionary.py        무결성 점검 + 매칭 시연
수질_표준사전_v1.xlsx      검수용 워크북 (5시트)
*.csv                   시드 데이터 (UTF-8 BOM)
```

## 규모

| 테이블 | 행 | 내용 |
|---|---|---|
| `measurement_terms` | 76 | 측정항목. 현행 법정 57 + 구 법정 1 + 비법정 관측항목 18 |
| `metadata_terms` | 30 | 측정소·측정일시·좌표 등 관측 메타 |
| `term_sources` | 19 | 출처 레지스트리 |
| `term_synonyms` | 332 | 동의어. **1행 = 1표기 × 1출처**, 각각 출처·수집일 보유 |
| `unresolved_columns` | 0 | 매칭 실패 큐 (운영 중 채워짐) |

## 왜 테이블이 이 구조인가

**사전이 둘인 이유** — `measurement_terms`는 "무엇을 쟀는가"이고 근거가 법령이다.
`metadata_terms`는 "언제·어디서·누가 쟀는가"이고 근거가 행정안전부 공공데이터 공통표준용어다.
근거 문서가 다르고, 검수 방법도 다르고, 검수할 사람도 다르다.

**동의어가 별도 테이블인 이유** — "동의어마다 출처와 수집일"을 남기려면 동의어 하나가 한 행이어야 한다.
초안처럼 `BOD5|생물학적 산소요구량|비오디`로 이어 붙이면 어느 표기를 어디서 언제 봤는지 적을 자리가 없다.
파이프 형태가 필요하면 `v_dictionary_flat` 뷰가 언제든 다시 만들어 준다.

**출처가 레지스트리인 이유** — 증거의 강도가 출처마다 다르다.
`term_sources.reliability`가 `legal`(법령 원문) / `standard`(정부 표준) / `spec`(기관 명세) /
`observed`(실데이터에서 관측) / `inferred`(AI·사람 추정)를 구분한다.
발표 자료에 인용할 때 `inferred`를 빼고 쓰면 된다.

## 초안 대비 정정 내역

법령 PDF 19쪽 전문과 국가법령정보센터 원문을 대조한 결과다. 여덟 가지가 바뀌었다.

### 1. 특정수질유해물질의 근거 별표가 틀렸다

초안은 카드뮴·수은·납 등의 법적 근거를 **별표 13의2**로 적었다. 원문 확인 결과:

- **별표 3** = 「특정수질유해물질」(제4조 관련) — **목록의 정본**. 33개 호 중 제11호 삭제로 실제 32종
- **별표 13의2** = 「특정수질유해물질 폐수배출시설 적용기준」(제35조의2 관련) — 목록이 아니라 기준농도표

사전에는 32종 전부에 `is_toxic_substance = true`와 `toxic_substance_basis = '물환경보전법 시행규칙 별표 3 제N호(원문표기)'`를 넣었다.
초안이 유해물질로 분류했던 **크롬(총크롬)은 특정수질유해물질이 아니다** — 6가크롬만 해당한다.

| 초안 표준명 | 별표 13 원문 | 조치 |
|---|---|---|
| 플루오린 | **플로오르(불소)함유량** | 표준명 교체, '플루오린'은 동의어로 강등 |
| 1,4-다이옥세인 | **1,4-다이옥산** | 표준명 교체 (아래 4번 참고) |
| 포름알데히드 | **폼알데하이드** | 표준명 교체 (아래 4번 참고) |
| 시안 / 크롬 / 카드뮴 … | **시안함유량 / 크롬함유량 / 카드뮴함유량** | '함유량' 접미가 법령 표기 |

### 3. 별표 13 항목 12개가 빠져 있었다

사염화탄소 · 1,2-디클로로에탄 · 니켈 · 디에틸헥실프탈레이트(DEHP) · 염화비닐 · 브로모포름 ·
에피클로로하이드린 · 톨루엔 · 자일렌 · 퍼클로레이트 · 비스(2-에틸헥실)아디페이트 · 안티몬

이 중 8개가 특정수질유해물질이다(니켈·톨루엔·자일렌·퍼클로레이트는 해당 없음).
현행 별표 13 나목의 54항목 + 가목의 3항목 = **57항목이 모두 들어갔다**
(PDF에서 항목명을 재추출해 교차 검증했고 `check_dictionary.py`가 매번 개수를 확인한다).

### 4. 두 법령이 같은 물질을 다르게 표기한다

초안의 `1,4-다이옥세인`과 `포름알데히드`는 AI가 지어낸 표기가 아니었다.
**환경정책기본법 시행령 별표 1(환경기준)의 정식 법령 표기**다. 물환경보전법 별표 13과 다를 뿐이다.

| 물질 | 물환경보전법 별표 13 | 환경정책기본법 별표 1 |
|---|---|---|
| 다이옥산 | 1,4-다이옥**산** | 1,4-다이옥**세인** |
| 포름알데히드 | **폼알데하이드** | **포름알데히드** |
| PCB | 폴리클로리네이티드**바이**페닐 | 폴리클로리네이티드**비**페닐 |
| 6가크롬 | 6가크롬함유량 | 6가 **크롬**(Cr6+) (공백) |
| 계면활성제 | 음이온계면활성제 | 음이온 **계면활성제**(ABS) (공백) |

먹는물 기준까지 넣으면 **세 계열**이 된다.

| 물질/항목 | 물환경보전법 별표 13 | 환경정책기본법 별표 1 | 먹는물검사규칙 별표 1 |
|---|---|---|---|
| 포름알데히드 | **폼**알데하이드 | **포름**알데히드 | **포름**알데히드 |
| Xylene | **자일렌** | — | **크실렌** |
| Fluoride | 플로오르(불소)함유량 | — | **불소** |
| Copper | 구리(**동**)함유량 | — | **동** |
| 총대장균군 | 총대장균군 | 총대장균군 | **총 대장균군** (공백) |
| pH | 수소이온농도 | 수소이온농도(pH) | **수소이온 농도** (공백) |

같은 법 안에서도 흔들린다. **별표 3**은 `1, 1-디클로로에틸렌`(콤마 뒤 공백), **별표 13**은 `1,1-디클로로에틸렌`(공백 없음).
별표 13 가목 표 하나 안에서 `생물화학적산소요구량`과 `생물화학적 산소요구량`이 함께 쓰인다.
같은 수도법령 안에서도 시행규칙 제22조의4는 `총대장균군`을 붙여 쓴다.

1:1 매핑이 아예 성립하지 않는 경우도 있다. 먹는물 기준은 대장균과 분원성대장균군을
**`대장균·분원성 대장균군` 한 항목으로 묶는다.**

> 이게 온톨로지가 필요한 이유의 가장 강한 증거다. 지자체가 제각각인 게 아니라 **법령끼리도 다르다.**

### 5. 초안에 있던 '폼산'은 별표 13에 없다

19쪽 전문 어디에도 없다. 코드 `WQ-042`는 재사용 방지를 위해 남기되 `review_status = 'rejected'`로 두었다.
삭제하지 않은 이유는 "이미 확인했고 근거가 없더라"를 기록으로 남기기 위해서다.

### 6-1. 먹는물 수질기준의 근거 법령은 흔히 잘못 알려져 있다

정수장·약수터 데이터 항목(탁도·잔류염소·일반세균 등)의 근거를 「먹는물관리법 시행규칙 별표 1」로
잡기 쉬운데 **틀렸다.** 그 별표는 「환경영향조사의 조사항목 등(제7조 관련)」이고,
먹는물관리법 시행규칙에는 수질기준 별표가 아예 없다(별표 1~10 전수 확인).

정본은 **「먹는물 수질기준 및 검사 등에 관한 규칙」 별표 1**〈개정 2021. 9. 16.〉 하나뿐이다.
먹는물관리법 제5조제3항과 수도법 제26조제2항이 **둘 다** 이 규칙 제2조로 위임된다.
즉 수돗물 수질기준의 정본도 이 별표다.

잔류염소는 상한과 하한이 서로 다른 법령에 나뉘어 있다.

| 구분 | 근거 | 값 |
|---|---|---|
| 상한 | 먹는물검사규칙 별표 1 제4호 가목 | 4.0㎎/L |
| 하한 | **수도법 시행규칙 제22조의2제1항제3호** | 유리잔류염소 0.1㎎/L 이상 |

흔히 말하는 "수돗물 잔류염소 0.1~4.0"은 단일 조문이 아니라 **두 규칙의 합성**이다.
법령상 항목명은 괄호까지 포함해 `잔류염소(유리잔류염소를 말한다)`이고,
수도법 시행규칙에서는 `유리잔류염소`로만 쓴다.

### 6-2. 배출허용기준에 없는 관측항목의 근거를 찾았다

용존산소·클로로필-a·분원성대장균군·헥사클로로벤젠은 별표 13에 없지만
**환경정책기본법 시행령 별표 1**에 있다. 각각 근거를 채워 넣었다. 주의할 점 둘:

- **클로로필-a와 총질소는 '하천'이 아니라 '호소' 기준 항목**이다. 하천 환경기준에는 없다.
- **전기전도도는 환경기준 별표 1에 없다**(전문 검색 0건). 공공데이터 공통표준용어에 `ELCD`로 등재돼 있을 뿐이다.

### 7. 단위가 법령마다 다르다

총대장균군은 별표 13이 `군수/㎖`, 환경기준이 `군수/100mL`다. **값을 그대로 비교하면 100배가 틀린다.**
클로로필-a도 법령 단위는 `㎎/㎥`인데 데이터는 `㎎/L`로 오는 경우가 있다.

### 8. 관측 메타는 대부분 이미 국가표준이 있다

행정안전부 공공데이터 공통표준용어(13,176건)를 전수 조회한 결과, 15개 개념 중 12개가 등재돼 있었다.

| 개념 | 표준 영문약어 | 도메인 |
|---|---|---|
| 측정소명 | `MSRSTN_NM` | 명V200 |
| 측정일자 / 측정일시 | `MSRMT_YMD` / `MSRMT_DT` | 연월일C8 / 연월일시분초D |
| 시료채취일자 | `SPCM_PCKNG_YMD` | 연월일C8 |
| 하천명 | `RVR_NM` | 명V100 |
| 위도 / 경도 | `LAT` / `LOT` | 위도N12,10 / 경도N13,10 |
| 소재지주소 / 도로명주소 | `LCTN_ADDR` / `ROAD_NM_ADDR` | 주소V200 |
| 시도명 / 시군구명 | `CTPV_NM` / `SGG_NM` | 명V40 |
| 기관명 | `INST_NM` | 명V200 |

경도의 표준 약어는 `LNG`나 `LON`이 아니라 **`LOT`**다.
서울시 API의 `MSRSTN_NM`은 이 표준을 그대로 따른 사례이고, 나머지 기관은 따르지 않았다.

등재되지 않은 3개는 대체 근거를 지정했다.

| 없는 개념 | 대체 표준 |
|---|---|
| 측정소코드 | 근접 표준 `측정지점번호 MSPT_NO`. 또는 단어 조합 `MSRSTN_CD`(기관표준용어) |
| 시군구코드 | `법정동시군구코드 STDG_SGG_CD`(코드C3) 또는 `법정동코드 STDG_CD`(코드C10) |
| 데이터기준일자 | `자료기준일자 DATA_CRTR_YMD`. '데이터'는 표준단어가 아니고 '자료'가 정식 |

수질 **항목** 쪽은 대부분 공통표준용어에 없지만(BOD·COD·DO·총질소·총인·클로로필 모두 0건),
`수소이온농도 HION_DNST` · `부유물질량 SSQTY` · `전기전도도 ELCD`는 등재돼 있다.

## PostgreSQL 적재

```bash
psql -d <db> -f schema.sql
psql -d <db> -f seed.sql
```

CSV로 넣고 싶으면 `schema.sql` 적용 후 `\copy`를 쓰면 된다(파일은 UTF-8 BOM).

> `schema.sql`과 `seed.sql`은 실제 PostgreSQL 파서(libpg_query/pglast)로 전 구문 파싱을 통과했다.
> 다만 이 환경에 PostgreSQL 서버가 없어 **실행 검증은 하지 못했다.** 처음 적재할 때 한 번 확인하기 바란다.

## 사전이 자라는 방법

```
새 데이터셋 컬럼명
      ↓
wq_match_column('생물학적 산소요구량')
      ↓
exact_standard / exact_synonym  → 자동 매핑
      ↓ (실패)
wq_record_unresolved(...)  → unresolved_columns 큐에 적재 (같은 표기는 seen_count만 증가)
      ↓
사람이 큐를 보고 판단
      ↓
wq_promote_unresolved(id, 'WQ-001', '박서연')
      ↓
term_synonyms에 출처·수집일과 함께 편입 → 다음부터 자동 매칭
```

```sql
SELECT * FROM wq_match_column('총소질소');
SELECT * FROM unresolved_columns WHERE status='pending' ORDER BY seen_count DESC;
SELECT * FROM v_synonym_conflicts;   -- 한 표기가 두 코드에 붙었으면 사전이 모순
SELECT * FROM v_source_coverage;     -- 어느 기관 데이터를 얼마나 흡수했는가
```

`fuzzy` 결과는 **자동 채택하면 안 된다.** 후보일 뿐이므로 사람이 확인하고 승격해야 한다.

## 매칭이 실제로 되는지

`python3 check_dictionary.py` — 무결성 6개 항목과 매칭 16건을 확인한다. 현재 전부 통과한다.

BOD 하나가 실데이터에서 불리는 여섯 가지 이름이 모두 `WQ-001`로 모인다.

```
생화학적 산소요구량            → WQ-001  (전북)
```

## 남은 일

측정항목 76건 중 68건이 `verified`, 1건이 `rejected`(폼산), **7건이 `draft`**로 남았다.

1. **근거 미확보 7건** — 전기전도도 · 인산염 인 · 용존총질소 · 용존총인 · 투명도 · 수위 · 유량.
   법정 기준 항목이 아니라 수질오염공정시험기준이나 측정망 운영계획 쪽을 봐야 할 것으로 보인다.
   수위·유량은 애초에 수질이 아니라 수문 관측값이라 이 사전에 둘지부터 정해야 한다.
2. **`metadata_terms` 13건 미확인** — 측정연도·측정월·용수구분명 등은 공통표준용어 13,176건과 아직 대조하지 않았다.
   `standard_basis`에 '미확인'으로 표시돼 있다.
3. **먹는물 별표 1의 나머지 항목** — 이번엔 실데이터에서 관측된 6개 항목만 넣었다.
   당진시 상수도 데이터가 60항목짜리이므로, 그걸 파싱하면 경도·증발잔류물·소독부산물 계열이 더 필요해진다.
4. **동의어 없는 측정항목 12건** — 톨루엔·퍼클로레이트 등. 공공데이터에 거의 안 나타나는 항목이라
   비어 있는 게 정상이지만, 폐수 배출 데이터를 받으면 채워질 것이다.
5. **`DRAFT_AI` 출처 동의어 미검수** — 초안의 AI 생성 표기다. 실데이터나 법령에서 확인되기 전에는
   발표 근거로 인용하지 말 것. (이번에 `불소`·`1,4-다이옥세인`·`포름알데히드` 3건은 실제 법령 표기로
   확인돼 정식 출처로 승격했다.)
6. ~~**인천시 wide 구조**~~ — **해결됨 (2026-08-06).** `<하천명>_<항목명>` 파싱 규칙을
   `pipeline/mapper.py`의 `_composite_lookup()`으로 구현했다. 임시로 넣어 뒀던 `draft` 동의어 4건
   (`시천천_심곡천*`)은 제거했다. 지점명이 사전에 남아 있으면 같은 지점의 컬럼이
   `WQ-009`와 `WQ-003@시천천심곡천`으로 갈려 출력이 어긋난다.
   인천시 파일 자동 매핑률 12.4% → 99.0%.
7. **`구분` 컬럼은 사전에 넣을 수 없다** — 인천에서는 측정일자(`2017-01-01`),
   제주에서는 분기(`1분기`~`4분기`)다. 같은 표기가 파일마다 다른 것을 가리키므로
   동의어로 등록하면 한쪽이 반드시 틀린다. 파일 단위 컨텍스트가 필요한 케이스이고,
   현재는 `unmapped`으로 남겨 사람 판정을 받는다.
