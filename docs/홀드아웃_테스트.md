# 홀드아웃 테스트 — 사전이 처음 보는 데이터에서의 정확도

## 왜 필요한가

`data/samples/` 6개 파일의 **자동 매핑률 98.2%는 in-sample 수치**다. 그 6개를 보면서 사전을 만들었기 때문에
성능 근거로 쓸 수 없다. 사전이 한 번도 보지 못한 파일의 첫 실행 숫자라야 정직한 증거가 된다.

## 1차 결과 (2026-08-08, 사전 동결 상태)

**충청남도 보건환경연구원 물환경측정망(하천) 2026년 6월 검사결과** — 69컬럼 / 1,980행

```
자동 매핑률 85.5% (59/69)   확인 필요 1.4% (1)   실패 13.0% (9)

in-sample 98.2%  →  홀드아웃 85.5%   =  −12.7%p
```

이 파일이 좋은 시험인 이유 — 기존 6개와 구조가 전혀 다르다.

- **2행 병합 헤더** (기존 6개는 전부 1행 또는 단순 2행)
- 컬럼명에 **내부 DB 필드코드 병기**: `년(WMYR)`, `채수일(WMCYMD)`, `측정깊이(WMDEP)`
- 컬럼명에 **자릿수 포맷** 괄호: `수온(0.0)`, `T-N(0.000)`, `Hg(0.0000000)`
- 날짜 컬럼이 6개 (년/월/회차 분리 + 검사년월일 + 채수일 + 채수시각 + 시작일/종료일)
- 중금속·휘발성유기화합물 30여 종, 컬럼명 안에 쉼표(`1,2-디클로로에탄`)

## 실패 9건의 정체 — "전부 사전 결손"이 아니다

| 유형 | 건수 | 항목 |
|---|---|---|
| **헤더 파싱 결함** | 2 | `UNNAMED_0`, `UNNAMED_1` |
| **비측정 메타 컬럼** | 4 | 특이사항(WMMN), 시작일(WMFDT), 종료일(WMTDT), 수정사유(…) |
| **진짜 사전 결손** | 3 | 조류, N핵산, Cl⁻(염소이온) |
| (확인 필요 1건) | 1 | 채수시각(WMCTM) — 72.7점 |

**실패 13%를 전부 "사전에 없는 항목"이라고 말하면 과장이다.** 실제 사전 결손은 3건(4.3%)뿐이다.

### 발견한 엔진 결함 — 2행 병합 헤더

`detect_header_row()`가 2행을 헤더로 고르는데, `지점명`·`지점번호(PT_NO)`는 1행에 **세로 병합**되어
2행이 빈칸이다. 그래서 **측정소명과 측정소코드가 통째로 소실**된다(→ `UNNAMED_0`, `UNNAMED_1`).

사전 문제가 아니라 파싱 문제다. `read_data_file()`에 "헤더 행 위쪽 빈 칸은 상위 행에서 채운다(forward-fill)"
로직이 없다. **1차 수치를 기록한 뒤에 고칠 것** — 홀드아웃 실행 전에 고치면 첫 실행 숫자가 오염된다.

### 오탐(false positive)은 0건

복합 컬럼명 분해가 잘못 발동해 엉뚱한 지점 라벨을 붙인 사례는 없었다(`지점명` 필드가 채워진 컬럼 0건).
자동 채택 59건은 전부 지점 라벨 없이 정상 매핑됐다.

## 채점 규칙 — 1차 실행 전에 고정할 것

결과를 보고 기준을 정하면 그 순간 홀드아웃이 아니다. 미리 정한다.

1. **자동 매핑률(재현율)과 오탐 건수(정밀도)를 반드시 분리 보고**한다. 매핑률만 쓰면 잘못된 매핑이 성공으로 잡힌다.
2. `목표수질_BOD` 같은 **기준값 컬럼이 측정값으로 매핑되면 오답**으로 센다.
3. 헤더 파싱 실패(`UNNAMED_*`)는 **사전 결손과 분리 집계**한다.
4. 파일 수와 **독립 기관 수를 함께 표기**한다(같은 기관 2개 파일은 독립 표본 2개가 아니다).
5. 1차 수치는 기록 후 재실행으로 갱신하지 않는다.

## 발표에서 말할 것

> "샘플 6개에서 98.2%가 나왔지만 그건 사전을 만들며 함께 본 파일입니다. 사전을 동결하고
> 처음 보는 충남 69컬럼 파일에 돌리니 85.5%였습니다. 실패 9건 중 진짜 사전 결손은 3건이고
> 나머지는 헤더 파싱 결함 2건과 비측정 컬럼 4건이었습니다. 사람이 3건을 판정해 사전에 넣고
> 다시 돌리면 N%가 됩니다. 이 상승폭이 저희가 만든 것입니다."

"세계 최초"보다 이 문단이 강하다. 실패를 분해해서 보여주는 팀은 숫자를 신뢰받는다.
