# output_holdout/review_queue.csv 판정 가이드 (충남 10건)

> ⚠️ 첫 화면에서 열어야 할 파일은 **`output_holdout/review_queue.csv`** 다.
> `output/review_queue.csv`(번호·구분 3건)는 샘플 6개 파일용이라 다른 파일이다.

## 채우는 칸

| 칸 | 무엇을 쓰나 |
|---|---|
| **사람판정** | 표준코드 직접 기입(예: `MD-001`) · 후보가 맞으면 `승인` · 아니면 `기각` |
| **판정자** | 본인 이름 |

`기각`이나 빈칸이면 사전에 반영되지 않는다. **모르면 비워두는 게 맞다** — 억지로 채우면 사전이 오염된다.

## 판정 근거는 어디에 쓰나

review_queue.csv에는 근거 칸이 없다. **근거는 사전에 반영할 때 남긴다.**

`apply_review.py`가 자동으로 남기는 것: 출처 파일, 수집 시각, 판정자 (`ontology/review_log.csv`).
**법령 조문 같은 근거는 사람이 `ontology/source/build_dictionary.py`의 note에 직접 적는다.**

즉 순서가 이렇다.

```
1) review_queue.csv 에 판정만 적는다          ← 여기선 코드만
2) apply_review.py 로 동의어를 사전에 넣는다   ← 출처·시각·판정자 자동 기록
3) build_dictionary.py 의 note에 근거를 적는다 ← 법령 조문은 여기
```

## 10건 판정안

### 판정할 필요가 없는 것 — 비워두기 (4건)

수질 항목도 관측 메타도 아닌 **파일 운영용 컬럼**이다. 표준 사전에 넣을 개념이 아니다.

| 원본명 | 왜 비워두나 |
|---|---|
| `특이사항(WMMN)` | 자유 서술 비고란 |
| `시작일(WMFDT)` · `종료일(WMTDT)` | 실험실 분석 기간. 측정일(MD-006)과 다른 개념이고 사전에 해당 항목이 없다 |
| `수정사유(구체적으로 입력하십시오…)` | 입력 안내문이 컬럼명에 들어간 것. 데이터가 아니다 |

**이 4건을 "실패"로 세면 안 된다.** 발표에서는 `비측정 컬럼 4건`으로 분리해 보고할 것.

### 승인 — 후보가 맞다 (1건)

| 원본명 | 후보 | 사람판정 | 확인 내용 |
|---|---|---|---|
| `채수시각(WMCTM)` | MD-006 (80.0점) | **`MD-012`** | ⚠️ 후보가 틀렸다. MD-006은 측정**일자**, 이건 **시각**이다. 사전에 `MD-012 측정시각`(MSRMT_TM, 시분초C6)이 이미 있으므로 그쪽으로 직접 기입 |

**후보 점수가 높다고 그대로 승인하면 안 되는 사례다.** 유사도 80점이 오히려 함정이었다.

### 직접 기입 — 사전에 개념이 있는데 표기가 없다 (2건)

| 원본명 | 사람판정 | 근거 |
|---|---|---|
| `지점명` | **`MD-001`** | 사전의 `측정소명`과 같은 개념. `측정소명`은 exact인데 `지점명`은 못 잡는다(44.4점) — 표기만 없는 것 |
| `지점번호(PT_NO)` | **`MD-030`** 또는 비워두기 | 후보 MD-030(채수지점번호)이 80점. 다만 MD-030 자체가 아직 draft(개념 동일성 미확인)라, **보수적으로 가려면 비워두고** 충남 정의서 확인 후 판정 |

### 새 항목이 필요하다 — 사전에 없는 개념 (3건)

이건 review_queue로 해결되지 않는다. **`build_dictionary.py`에 새 행을 추가**해야 한다.

| 원본명 | 실제 정체 | 어떻게 할까 |
|---|---|---|
| `Cl-(0.0)` | **염소이온**. 사전엔 `WQ-070 잔류염소`만 있는데 이건 다른 물질이다 | 새 측정항목 추가 필요 |
| `N핵산(0.0)` | **노말헥산추출물질**의 축약 표기로 추정 | 사전에 `WQ-012 노말헥산추출물질함유량 광유류`·`WQ-013 동식물유지류`가 있다. **둘 중 어느 쪽인지 충남에 확인 후** 해당 코드로 판정. 확인 안 되면 비워둘 것 |
| `조류(0)` | 조류(藻類) 개체수로 추정. 사전에 `WQ-061 클로로필-a`는 있으나 다른 지표 | 개념 확인 후 새 항목 |

**`N핵산`은 특히 조심하세요.** 광유류(WQ-012)와 동식물유지류(WQ-013)는 법령상 배출허용기준이 다른 별개 항목입니다. 추측으로 둘 중 하나를 고르면 안 됩니다.

## 새 항목을 추가할 때 근거 쓰는 법 — 염소이온 예시

`build_dictionary.py`의 측정항목 영역에 추가한다. `note`(마지막 위치 인자)가 근거 칸이다.

```python
m("WQ-0NN", "염소이온", "Chloride", "Cl-", "㎎/L", "이온류",
  legal_basis="...",          # ← 법령을 실제로 확인하고 적을 것
  legal_article="...",
  note="충남 물환경측정망 CSV의 'Cl-' 컬럼(2026-08-08 대조). "
       "잔류염소(WQ-070)와 다른 물질이므로 별도 항목으로 둔다")
```

**확인하지 않은 법령을 적으면 안 된다.** 근거를 못 찾았으면 `legal_basis`를 비우고
`review_status="draft"`로 두는 게 맞다 — 폼산을 rejected로 처리한 것과 같은 원칙이다.

염소이온이 어느 법령에 있는지는 직접 확인이 필요하다. 후보:
- 먹는물 수질기준 규칙 별표 1 (심미적 영향물질에 염소이온 250㎎/L 기준이 있는지)
- 물환경보전법 시행규칙 별표 13 (배출허용기준에 있는지 — 아마 없을 것)
- 없으면 `수질오염공정시험기준`을 근거로 쓰고 note에 "법정 기준 없음, 공정시험기준 항목"이라 적는다

## 예상 결과

10건 중 실제로 사전에 반영될 수 있는 건 **지점명(MD-001), 채수시각(MD-012)** 2건이 확실하고,
새 항목 3건은 개념 확인이 필요하다. 전부 반영하면:

```
1차 85.5%  →  2차 88.4% (2건 반영 시)  ~  92.8% (5건 전부 반영 시)
```

**나머지 4건(비측정 컬럼)은 영원히 unmapped로 남는 게 정답이다.** 그래서 2차가 100%가 되지 않고,
그게 정직한 결과다. 발표에서 "왜 100%가 아닌가"를 먼저 설명하면 신뢰를 얻는다.
